## Post-audit clarification (recorded after implementation testing)

The initial controlled-401 reproduction for U1 was incomplete: the server session remained valid, so the login screen could automatically return to Settings. That observation alone did not establish a genuine session-expiry blocker. The original baseline log is retained. A refined test invalidates the real server session before delivering the pending request's 401 and confirms login with no protected draft. The guard now explicitly permits expiry navigation even while busy (unit covered); this is a defensive safety fix, not evidence of a previously demonstrated data leak. No confirmed P0/P1 remains in tested flows.

Further targeted findings resolved during implementation: a plan-only historical as-of selector must derive its hidden start date safely; unsubmitted filter changes must not change displayed price-version dates, API retries or onward links; and the API's LIVE_SHOPIFY_NOT_VERIFIED state needed plain-language display. These were handled without new domain APIs or model changes. Independent participant validation remains NOT VERIFIED.
